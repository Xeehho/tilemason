# TileMason 编辑器页面布局与样式修复/重构文档

版本：2026-09-21  
依据：用户提供的 1600×900 编辑器截图 + 当前 `main` UI 源码  
范围：仅讨论编辑器壳层、图层/预制件、工具栏、素材浏览、快捷栏、状态栏的布局与样式；不改变地图数据模型、素材包格式和导出格式。

## 1. 结论先行

当前页面的问题不是单个控件不好看，而是多个独立 `CanvasLayer` 使用固定偏移后叠在同一个画布上，导致“工具、素材、地图”三种工作空间互相争夺屏幕：

- 左侧图层区过密，预制件区与图层区上下硬切，宽度和内容计数不一致；
- 顶部工具栏侵入左侧图层区和画布安全区，图标语义弱，依赖悬浮提示才能理解；
- 右侧素材浏览器把分类树、搜索、标签、最近使用和缩略图全部塞进 380px 固定栏，长名称大量截断，缩略图列被挤压；
- 底部快捷栏与状态栏共用底部空间，快捷栏标签/图标落入状态栏安全区，状态栏又塞入过长的快捷键串；
- 画布本身仍有较大空白，但两侧控件已经出现裁切、拥挤和低可读性，说明空间分配方向错误；
- 样式 token 已有基础（暗色、金色强调、13px 字体），但没有形成“工作区/停靠区/浮层/危险提示”的层级系统。

推荐采用“固定安全区 + 可调整双侧 Dock + 中央画布”的壳层重构。第一阶段不改业务逻辑，只把现有控件从绝对定位迁移到容器布局；第二阶段再改善素材卡片和图层行的内容密度。

## 2. 当前页面证据与源码对应

| 区域 | 截图表现 | 当前实现证据 | 判断 |
|---|---|---|---|

| 顶部工具栏 | 从左侧中部开始横跨画布；没有标题、分组或文字说明 | `src/main.gd` `offset_left=200, offset_right=660, offset_top=4`；`Toolbar` 每按钮 40×38 | 绝对偏移造成侵入；图标识别成本高 |
| 右侧分类 | 最近、标签/分组、9 类素材全部平铺在窄树中，长名称被截断 | `AssetPanel.PANEL_WIDTH=380`，分类树最小宽 150，主界面右侧固定 380 | 信息架构过载，分类与素材结果没有足够呼吸空间 |
| 右侧缩略图 | 搜索框、刷新按钮、三列缩略图共享剩余宽度；大图建筑在边缘被裁切/第二列难完整呈现 | `GridContainer.columns=3`，缩略图最大边 64，右侧面板不响应窗口宽度 | 列数固定不适配；缩略图与名称信息分离 |
| 底部快捷栏 | 只显示图标，数字/名称依赖 tooltip；底部垂直空间不足时容易贴住状态栏 | `Hotbar` 槽尺寸 48，主界面 `offset_top=-84, offset_bottom=-30` | 需要独立安全区和可见数字键标识 |
| 状态栏 | 一行塞入坐标、工具、素材、文件名和整套快捷键，字号小、信息权重相同 | `StatusBar` 高 26px、字体 13；`refresh_status()` 生成超长串 | 应拆成状态段，快捷键移到帮助/tooltip |
| 颜色/层级 | 面板、列表、画布都偏暗；选中主要靠金色边框；分隔线弱 | `app_theme.gd` 已有 BG_PANEL/BG_DARK/ACCENT，但边界色只约 0.06 alpha | 需要更清晰的 Surface/Divider/Focus/Warning 层级 |

## 3. 具体不合理之处

### 3.1 空间分配不合理

1. **中央画布没有获得优先级**：左右 Dock 采用固定宽度，工具栏和快捷栏又以独立浮层压入画布；结果是画布“看起来很空”，可用编辑区却被边缘控件侵入。
2. **停靠区没有安全边界**：顶部工具栏与左图层重叠，底部快捷栏与状态栏相邻，控件缺少统一的 8px/12px 内边距。
3. **尺寸契约冲突**：图层控件声明最小宽 210px，父节点只给 190px；这是布局 bug，不是用户审美偏好。
4. **固定列数不适配**：素材网格固定 3 列，在窄面板会裁切，在宽面板又浪费空间；应由可用宽度计算列数或切换列表/网格模式。
5. **垂直分区写死**：预制件固定占左下 220px，即使无预制件也占据空间；应该可折叠、标签化或按内容自适应。

### 3.2 信息架构不合理

1. **素材分类和用户内容混在同一层级**：最近、收藏、标签、素材组、9 个核心分类同时出现在一棵树里，用户无法快速判断“这是系统分类还是我的筛选结果”。
2. **素材结果缺少卡片信息**：截图中主要看到大图，名称、占格、锚点、连接方向、来源包需要依靠 tooltip；对于美术/策划工作流不够可扫描。
3. **工具栏只有图标**：图标虽有 tooltip，但首次使用必须逐个悬停；撤销/重做、预制件、油漆桶的形状语义不够强，不能只依赖颜色高亮。
4. **状态信息没有分级**：坐标、当前工具、当前素材、文件名、十余个快捷键都以同一字号和分隔符串联，重要状态反而不突出。
5. **预制件被当作永久面板**：预制件是低频管理操作，却固定占用左下高 220px；图层是高频操作，不应与低频列表硬切同一列。

### 3.3 视觉与交互问题

1. **对比度层次不足**：画布网格线、面板底、列表底、分隔线接近，面板边界需要更明确的 Surface-1/Surface-2/Divider 三层。
2. **控件命中区过小**：图层行 26px，名称/复选框/锁/滑杆/删除按钮密集排列；建议常用操作命中区不低于 32px。
3. **选中状态过度依赖金色**：工具栏、素材、活动图层都用金色，语义混在一起；应区分“当前工具”“当前素材”“警告/阻挡”。
4. **警告状态没有独立层级**：遮挡道路的橙色框是正确方向，但需要配合简短文字/图标提示，不能只依赖边框颜色，避免色觉差异导致漏读。
5. **文本截断没有补偿机制**：长素材名和图层名被省略时，缺少稳定的 tooltip、详情区或展开方式；用户无法在列表中确认当前对象。
6. **底部内容容易被遮挡**：快捷栏和状态栏都贴近窗口底边，窗口缩放或系统字体变大时，最先出现裁切。

## 4. 推荐目标布局

### 4.1 壳层结构

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 顶栏：文档名 / 保存 / 撤销重做 / 工具组 / 检查 / 导出 / 帮助         │ 48px
├───────────────┬──────────────────────────────────────┬───────────────┤
│ 左 Dock        │                                      │ 右 Dock        │
│ 图层（主）     │                                      │ 搜索/筛选      │
│                 │                                      │ 分类/标签       │
│ 选中层详情     │             中央可编辑画布            │ 素材网格/列表   │
│                 │                                      │ 资产详情         │
│ [预制件][检查] │                                      │                 │
├───────────────┴──────────────────────────────────────┴───────────────┤
│ 快捷栏：橡皮 | 1..9 素材槽（独立安全区，必要时可隐藏）                 │ 64px
├──────────────────────────────────────────────────────────────────────┤
│ 状态段：坐标 | 当前工具 | 当前素材/图层 | 文件状态 | [?]快捷键帮助     │ 30px
└──────────────────────────────────────────────────────────────────────┘
```

核心原则：

- 顶栏、底栏和两侧 Dock 先占位，画布只使用剩余矩形，不允许浮层覆盖安全区；
- 左右 Dock 可拖拽调整宽度，可一键折叠；
- 预制件和检查结果进入左 Dock 的标签页/抽屉，不再永久切走图层空间；
- 素材分类、筛选和缩略图属于同一右 Dock，结果区根据剩余宽度自适应；
- 热键仍保留，但 UI 必须能在不看 tooltip 的情况下理解当前工具和选中素材。

### 4.2 建议尺寸契约

| 区域 | 默认 | 最小 | 备注 |
|---|---:|---:|---|
| 顶栏 | 48px | 44px | 统一按钮 36×36，分组间 12px |
| 左 Dock | 260px | 224px | 图层名称、计数、锁定和透明度不挤压 |
| 右 Dock | 400px | 320px | 分类树 116–136px，其余给结果区 |
| 快捷栏 | 64px | 56px | 橡皮 + 1–9 槽，显示数字角标 |
| 状态栏 | 30px | 28px | 只显示状态段，快捷键进入帮助浮层 |
| 画布 | 剩余空间 | 640×480 | 不被任何 Dock 覆盖 |

1600×900 目标下建议：左 260 + 画布约 940 + 右 400；任何一侧调整都应压缩画布而不是覆盖画布。1280×720 下进入紧凑模式：左 224、右 320，预制件/详情默认折叠。

## 5. 组件重构建议

### 5.1 从绝对定位改为单一 Shell 容器

新增一个 UI 壳层（可命名 `EditorShell`），采用 `VBoxContainer`：

1. `TopBar`：标题、保存、撤销/重做、工具按钮、检查、导出、帮助；
2. `BodyRow`：`LeftDock` + `CanvasHost` + `RightDock`；
3. `HotbarHost`：独立 56–64px 安全区；
4. `StatusHost`：独立 28–30px 状态段。

现有 `LayerPanel`、`PrefabPanel`、`AssetPanel`、`Toolbar`、`Hotbar`、`StatusBar` 保留信号和业务方法，只改父节点与尺寸管理。避免继续通过多个 `CanvasLayer` 设置 `offset_left/right/top/bottom` 互相覆盖。

### 5.2 左 Dock：图层优先，预制件/检查页签化

- 图层行改为两行或“名称区 + 操作区”：第一行显示拖柄、名称、内容计数和活动层；第二行显示显隐、锁、透明度、更多菜单。
- 名称区允许省略，但 hover 必须显示完整名称；双击重命名时使用整行编辑框，不与按钮争抢宽度。
- `+方块层`、`+物件层` 合并为“添加层”按钮，弹出两种类型选择，减少底部横向拥挤。
- 预制件改为左 Dock Tab：`图层 | 预制件 | 检查`；无预制件时不额外占固定高度。
- 删除、排序、重命名放进一致的更多菜单，减少每行常驻按钮。

### 5.3 顶栏：工具分组 + 可理解状态

建议分组：

- 绘制：画笔、直线、矩形、油漆桶、橡皮；
- 选择：选择、吸管；
- 组织：预制件、撤销、重做；
- 交付：F8 规则、F9 检查、Ctrl+E 导出。

按钮仍可使用图标，但至少提供数字/字母角标或组标题；当前工具同时显示图标、短名称和快捷键。选中状态使用金色边框，警告使用橙色，锁定使用灰色锁图标，避免所有状态都只靠金色。

### 5.4 右 Dock：统一素材浏览器

建议从“分类树 + 结果网格”重构为：

1. 顶部固定搜索框，支持名称、asset id、标签；
2. 下一行筛选 chip：最近、收藏、标签、核心分类；
3. 分类树默认只显示核心分类，用户组/素材包折叠在“来源”下；
4. 结果区支持网格/列表切换，网格列数按宽度计算，不固定 3 列；
5. 素材卡片包含缩略图、名称、`16×16`/`3×3格`、锚点 `▽/△`；hover 或右侧详情显示完整信息；
6. 右侧 Dock 内部允许拖拽分隔线，分类区宽度建议 120–136px；
7. 面板过窄时切换为“单列列表 + 预览”，不让建筑缩略图被裁切。

### 5.5 快捷栏与状态栏分离

- 快捷栏使用 56–64px 安全区，槽位显示 `1..9` 角标；橡皮单独标注 `E`，空槽仍有可见边框。
- 快捷栏只承载快速选择，不再承担说明文本；完整说明放 tooltip/帮助面板。
- 状态栏拆成四段：`坐标`、`工具`、`素材/活动层`、`文件状态`；右侧增加 `? 快捷键` 按钮。
- 文件未保存用小圆点/文字“未保存”，保存完成显示“已保存”；不要把十余个快捷键持续占满底部。

### 5.6 视觉 token 调整

保留当前暗色基调和金色主强调，但补齐四层 Surface：

```text
Canvas       #4c4c4c（保持像素画布基准）
Surface-1    #26262c（Dock/主面板）
Surface-2    #1c1d22（搜索框/列表/输入）
Surface-3    #34353e（按钮/卡片）
Divider      #555761（至少 1px，可见但不抢焦点）
Text         #e4e5ea
Text-dim     #b3b5bf（提高当前  #9a9ca6 的可读性）
Accent       #f0c560（选中/焦点）
Warning      #f29a52（遮挡/检查警告）
Danger       #e56b6f（删除/错误）
```

字号建议：标题 15–16px、正文/列表 13–14px、辅助信息不低于 12px；所有点击目标至少 32×32px。分隔线和面板边界应以真实像素取证确认，而不是只看颜色定义。

## 6. 实施顺序

### 阶段 A：壳层修复（低风险，优先）

- 建立 `EditorShell`/`BodyRow` 容器；
- 将 5 个独立 `CanvasLayer` 的绝对偏移迁移到容器子节点；
- 解决图层 210px vs 190px 宽度冲突；
- 给顶部/底部建立安全区，确保工具栏、快捷栏、状态栏不覆盖画布；
- 在 1600×900、1280×720 下截图回归。

### 阶段 B：右侧素材浏览器

- 搜索、最近、收藏、标签和分类统一为筛选模型；
- 分类树/结果区可拖拽分隔；
- 网格列数自适应；
- 卡片补名称、尺寸、占格、锚点；
- 增加面板布局探针，断言没有横向裁切和负宽度控件。

### 阶段 C：左侧图层/预制件与底部信息

- 图层两行结构与活动层高亮；
- 预制件/检查页签化；
- 快捷栏数字角标和安全区；
- 状态栏拆段，快捷键帮助单独弹出。

### 阶段 D：视觉验收与交互回测

- 更新截图探针的固定采样点，不把旧绝对坐标直接沿用；
- 新增 1600×900、1280×720、窄 Dock、长名称、空预制件、9 类素材的截图样例；
- 用户手工验证：拖拽 Dock、折叠/恢复、工具栏点击、素材搜索、标签、预制件、导出和版本历史；
- 运行现有全量探针，确认 UI 重构没有影响地图/导出数据。

## 7. 验收标准

### 必须通过

- 1600×900：工具栏、图层、素材面板、快捷栏、状态栏无互相覆盖；
- 1280×720：画布仍至少 640×480，所有核心按钮可点，长文本有省略+tooltip；
- 左 Dock 默认宽度 ≥224px，图层名称、计数、锁、显隐和透明度不发生横向裁切；
- 右 Dock 默认宽度 ≥320px，建筑缩略图完整显示，网格列数不固定为导致裁切的 3 列；
- 快捷栏与状态栏之间存在可见安全间距，槽位数字/当前工具可识别；
- 当前工具、活动图层、选中素材、道路遮挡警告至少有颜色之外的文字/图标表达；
- 所有现有功能探针、场景导出探针、截图取证和性能探针回归通过；
- 运行一次真实窗口手工回测，不能只以 headless 或静态截图替代。

### 建议指标

- 新用户不看 tooltip，1 秒内能判断当前工具；
- 3 次操作内完成“搜索一个素材→选中→放置”；
- 5 秒内从图层页切到预制件/检查页并返回；
- 任何名称被截断时，hover 立即能看到完整文本；
- 不同系统缩放/窗口尺寸下不出现负宽度、重叠、裁切或底部遮挡。

## 8. 不建议的修复方式

- 不建议单纯把右侧面板从 380px 加宽到 500px；这只会继续侵蚀画布，不能解决信息架构问题。
- 不建议继续新增 `CanvasLayer` 和 `offset_*` 叠加；布局边界会越来越难证明。
- 不建议把所有快捷键继续拼进状态栏；快捷键需要帮助面板、tooltip 和可搜索命令表。
- 不建议把素材名全部改短来迁就窄栏；应提供自适应列宽、详情区和完整 tooltip。
- 不建议用更亮的金色解决所有可见性问题；应先建立 Surface、Divider、Warning、Danger 的语义层级。

## 9. 本文档交付状态

本文档是布局/样式分析与重构方案，不修改当前功能代码。下一步若进入实现，应先做阶段 A 壳层修复并保留现有信号接口，再按阶段 B–D 逐步验收。
